# Agent 人工介入规则

> 状态：按 Agent v0.2 更新的业务规则。接口与实施说明见 [AGENT_API.md](./AGENT_API.md)。

## 核心原则

Agent 应先使用业务规则、上下文和用户记忆理解请求。只有仍然无法形成可执行操作时，才请求用户介入。

人工介入用于补充必要信息、确认 AI_ESTIMATED 候选，以及确认拟新建的私人物品或存储空间。信息完整的确定性写入不增加固定确认。

## 需要人工介入的场景

### 1. 批量写入中存在未确定的信息

批量入库、增加或消耗时，如果部分项目的数量、单位或包装关系无法确定，应汇总所有问题，让用户一次性补充。

例如：

- “一袋米”无法确定一袋对应多少重量。
- “一些苹果”无法得到可执行数量。
- 同一批数据混用了盒、袋、杯、克等单位，且部分换算关系未知。

### 2. 无法确定具体库存批次

同一物品匹配多个库存批次，并且业务规则和用户记忆都无法确定目标时，让用户选择具体批次。

如果已有可验证的适用规则或明确偏好，例如最早到期且没有并列批次，则自动选择。当前没有结构化开封状态，不能凭空推断已开封批次。

### 3. 无法生成可执行操作

Agent 使用单位描述、上下文、业务规则和用户记忆后，仍无法判断数量、单位、目标或操作类型时，只询问完成操作所需的最少信息。

例如用户表达相互矛盾，无法判断是增加、消耗还是盘点。

## 不需要人工介入的场景

- 单项且信息明确的操作。
- Agent 能够通过单位描述处理的模糊表达。
- 已有可靠用户记忆能够确定批次选择。经验单位关系仍是估算，需要确认候选。
- 能够按照业务规则完成的单位标准化。
- 所有项目均已理解清楚的批量写入。
- 普通库存查询、临期查询和结果整理。

## 多项请求流程

```text
解析全部项目
→ 使用单位规则、上下文和用户记忆
→ 收集仍未确定的信息
→ 信息明确的项目先逐项提交
→ 用户集中补充或确认其余候选
→ 每项独立提交，独立成功或失败
```

普通澄清完成后不增加额外确认；估算或新增关联对象的候选需要确认。某项失败不回滚已经成功的项目。

## 用户记忆规则

- 记忆只能在适用的用户、物品、单位和条件范围内使用。
- 有明确适用记忆时优先自动处理，减少重复询问。
- 没有适用记忆时允许模型用自身知识估算并展示候选；记忆冲突或适用条件不明确时请求补充。检索失败不能当作没有记忆。
- 是否保存新的单位关系或批次偏好，应由用户明确选择。

## 第一版判断规则

```text
规则或记忆能够确定
→ 自动处理

仍有必要信息无法确定
→ 集中请求用户补充一次

用户补充完成
→ 直接执行
```
