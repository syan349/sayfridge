# Agent 图文输入：前端接入清单

这里说明用户操作与界面流程。字段、限制、错误码和报文只在
[API 参考第 9 节](API_REFERENCE.md#9-agent-v02--chat-resume-and-recovery)维护。
后端已提供协议；各客户端的实际接入完成度以对应组件代码和联调结果为准。

## 先理解一次入库

```text
用户发送“把这些牛奶录入冷藏室”＋照片
    → chat 返回候选
    → 界面显示数量、位置及确认按钮
    → 第一次响应结束，等待用户
用户点击确认
    → resume 执行入库
    → 界面显示每项实际结果
```

文字示例：“买了 2 kg 西红柿”未指定位置时直接使用默认空间；只有默认空间不可用或真实歧义才追问。用户可直接通过 chat 补充“放冰箱里”，也可使用原 resume 接口。明确的新空间可随入库创建。

上传照片不代表确认入库。两次请求使用两条响应流，不让连接一直等用户点击。
只问“这是什么”时展示回答；只发图片时，Agent 可能先询问用途。

## 用户操作 → 接口 → 界面变化

| 用户操作 | 前端调用 | 界面如何变化 |
| --- | --- | --- |
| 输入文字，或添加照片后发送 | chat | 显示处理进度，然后展示回答或入库候选 |
| 用语音输入 | 前端先转成可编辑文字，再调用 chat | 用户编辑、发送后才提交；不上传音频 |
| 回答普通对话问题，尚无待处理候选 | chat | 继续对话，保留会话 |
| 补充某个候选缺失的信息 | chat 或 resume | 更新该候选，缺信息时保持待补充 |
| 修改数量、位置或新物品的分类 | chat 或 resume | 重新计算；图片或用户要求核对时等待确认 |
| 对某个候选补拍标签 | resume | 图片归到该项目，更新候选并重新核对 |
| 确认一项或所选多项 | resume | 分别显示成功、失败或仍待处理的项目 |
| 取消一项 | resume | 标记该项取消，不撤销其他已成功项目 |
| 刷新页面或网络中断 | state | 恢复当前业务进度，再决定继续确认还是恢复原请求 |

统一输入框提供拍照、相册和文字附件，不要求先选物品/小票模式。发送前允许预览、
移除、重拍及压缩图片。新请求可继续发送，后端保留原待处理任务。

## 卡片和状态怎么展示

- 候选卡片显示物品名称、分类、规格、实际入库数量单位、日期、位置和待核对说明。
- 图片候选未确认前，显示“待核对”，不能显示“已入库”；缺必需信息时先让用户补充。
- 同一个业务项目更新原卡片；修改和补图后，按钮必须操作新候选，不能沿用旧版本。
- 确认所选是逐项处理，一项失败不会撤销其他成功项。按每项结果更新，不统一标为成功。
- 等待项目的简短问题保存在 display.question，并通过 text_delta 返回；恢复页面可直接展示保存的问题，不重新生成或重复发送操作。旧候选没有该字段时继续使用已有展示。
- 回复结束只意味着停止加载。等待输入时保留操作按钮；全部结束时仍检查每项结果。
- 断线不等于失败。先查状态，不要新建请求重复入库；重试遵循接口参考的原请求规则。
- 保留本地缩略图和发送中的原请求。状态接口恢复业务进度，不提供完整聊天/图片历史。

## 连续聊天与数量变更

- 后端已支持待处理期间继续向 `/agent/chat` 发送补充、修改、确认、取消或独立查询。
  继续使用原 conversation_id，网络重试沿用原 request_id；无需为上下文整理创建新聊天。
- `/resume` 继续兼容弹窗和按项目操作。旧 proposal_id 已过期时刷新状态，不重复提交旧确认。
- 估算换算默认直接执行并标注估算；图片识别和用户明确要求先确认的操作仍返回待确认状态。
- 空间列表新增 is_default，登录自动补齐默认空间；可用空请求体调用
  `POST /api/v1/storage-spaces/{id}/default` 更改默认空间。
- 当前余额单位跟随本次操作，不一定等于初始单位；显示现有 display_amount + display_unit，
  保留 is_estimated。普通整件估算的整数结果由后端生成，AI 反馈也使用该结果，
  不依靠前端隐藏小数。没有新增数量状态字段或特殊展示字段。
- 聊天输入框、弹窗和默认空间选择界面的调整仍由前端负责，本次只交付后端接口行为。
